Light shows across the table

The buttons know where they sit, so instead of six lights doing the same thing they can do one thing together. These are proposals, drawn with the real NeoHEX layout (37 pixels in rings) and the real player colours. Click a button to make it the origin; drag the speed.

click a button to choose the origin

How it would work

One message per button, once, when the show starts. Each button then draws its own slice on its own clock, the way pulse already breathes in step using p. No message per step, so the sleepy radios and the hub's retries don't matter, and six buttons stay in time to a few milliseconds.

{"t":"show","dev":"A1B2C3D4E5F6","k":"chase","i":2,"n":6,"c":"ff8a1f","d":3000,"p":0}
  • k which show. i this button's seat, counting clockwise from the speaker, of n seats. c its own colour. d one lap of the show in ms. p how far in, so a button that hears it late still lands in step.
  • Shows that need an origin (a ripple from whoever scored, a hand-off from one player to the next) carry o, the origin seat, and for the hand-off to.
  • A one-shot show ends by itself and the button goes back to its last led. A looping one runs until the next led.
  • In the app this is still one interface: the engine says "fanfare, seat 2 of 6" and the on-screen buttons draw the same functions as the firmware, from this page.
