# Pax Buttonica

A Twilight Imperium 4 turn tracker (web app on Vercel) paired with glowing physical player buttons
(ESP32-C3 → ESP-NOW → USB hub → Web Serial). Live at https://pax-buttonica.vercel.app.
Private GitHub repo: rubiconRiver/pax-buttonica. Owner: Garett (Canada; knows software, new to electronics and PCBs, so explain hardware in plain terms).

## Layout

| Path | What |
|---|---|
| `src/engine/` | Pure rules engine (`reduce`, `deriveOutputs`), vitest tests |
| `src/` (rest) | Vite + React + TS app: simulated buttons, demo, play, scoreboard, phones-as-buttons |
| `api/` | Vercel functions on Neon Postgres (profiles, clips, table). No auth yet, by choice |
| `docs/` | `BUTTON_STANDARD.md` (wire protocol), `HARDWARE.md` (build guide), `SHOPPING.md`; the first two are rendered on the site at `/standard` and `/hardware` |
| `firmware/` | Arduino sketches: `hub/`, `button/` (+ `config.h`) |
| `hardware/pcb/` | Carrier board, generated by `make_board.py` (KiCad 10 `pcbnew`), gerber zip, renders |

## Commands

```bash
npm run dev          # vite
npm test             # vitest (engine)
npm run typecheck    # app + api
npm run build
npx --yes vercel@latest --prod --yes   # deploy (the installed vercel CLI fails on Node 24)
```

Firmware (arduino-cli can't see the sketchbook libraries from the sandbox, so pass them):

```bash
arduino-cli compile -b esp32:esp32:esp32c3:CDCOnBoot=cdc \
  --library ~/Documents/Arduino/libraries/Adafruit_NeoPixel \
  --library ~/Documents/Arduino/libraries/ArduinoJson firmware/button
```

Board:

```bash
cd hardware/pcb
/Applications/KiCad/KiCad.app/Contents/Frameworks/Python.framework/Versions/Current/bin/python3 make_board.py
kicad-cli pcb drc pax-button.kicad_pcb     # must stay at 0 violations, 0 unconnected
```

## Ground rules

- Game logic lives in the web app. Hub and buttons stay dumb: report presses, show what they're told.
- The standard button has no speaker; the laptop plays every sound.
- The UI has to feel crisp and look like TI (chamfered frames, not bubbly). The site doubles as a recruiting demo.
- Nothing on the hardware side has been flashed or manufactured yet. Say "compiles" or "passes DRC", never "works", until it has run on real parts.
- Garett's standing instruction: commit, push and redeploy when a round of changes is done.

## Working in parallel

Several Claude sessions may be open on this repo at once, each in its own git worktree and branch. Stay in your lane:

- **App session:** `src/`, `api/`, `e2e/`, build config.
- **Hardware session:** `firmware/`, `hardware/`, `docs/HARDWARE.md`, `docs/SHOPPING.md`, `docs/BUTTON_STANDARD.md`. If the protocol has to change, change the doc and the firmware, and leave a note for the app session rather than editing `src/hardware/` yourself. Hardware status and open questions are in `hardware/HANDOFF.md`.

Merge to `main` with small commits, rebase before pushing, and only the session that touched `src/`, `api/` or `docs/` needs to redeploy.
